# قرارداد داده — نسخهٔ ۱

هدف، تبدیل‌پذیری به نماهای مختلف و امکان افزودن حوزه‌های تازه است. قالب نمی‌تواند بدون هیچ تبدیل‌کننده‌ای به هر نرم‌افزار ممکن وارد شود؛ اما اطلاعات اصلی و ارجاع‌ها را نگه می‌دارد تا بتوان برای خروجی تازه adapter نوشت.

## سه لایه

۱. **منبع:** متن اولیه، نقش نویسنده، لینک، ترتیب مشاهده‌شده و محدودیت دسترسی. نوشتهٔ زبان‌آموز ممکن است اشتباه داشته باشد؛ نوشتهٔ دستیار هم خودبه‌خود حقیقت تأییدشده نیست.

۲. **دانش:** جلسه، مفهوم، مدخل، معنی، مثال، Writing، اصلاح، تمرین و ارتباط. این‌ها محتوای اصلی و قابل انتقال‌اند.

۳. **نمایش:** گراف، تخته، جدول، جزوه و فلش‌کارت. رنگ، مختصات و تنظیمات GSAP در دادهٔ اصلی ثبت نمی‌شوند. تنظیمات نمایش و پیشرفت شخصی بعداً جدا نگهداری خواهند شد.

## رکوردهای مستقل

| نوع | مسئولیت |
|---|---|
| `subject` | حوزهٔ مطالعه؛ مثل زبان، تاریخ یا برنامه‌نویسی |
| `source` | منشأ اطلاعات و محدودهٔ دسترسی به آن |
| `session` | رویداد مطالعه یا کلاس و مطالبی که پوشش داده |
| `concept` | مفهوم قابل ارجاع در چند جلسه |
| `entry` | واژه یا عبارت، معناهای مستقل، نمونه‌ها و محل‌های تکرار |
| `collection` | خانوادهٔ کلمات، مجموعهٔ واژگان یا ترتیب مطالعه |
| `note` | بلوک‌های متن، مثال، فرمول، مقایسه و سؤال |
| `writing` | متن زبان‌آموز، متن نمونه یا نسخهٔ بازبینی‌شده |
| `correction` | متن اولیه، جایگزین، توضیح و منبع هر دو |
| `exercise` | صورت تمرین، پاسخ‌ها، قابلیت ارزیابی و کمبودها |
| `resource` | تصویر، صوت، سند یا فایلِ موجود یا مفقود |
| `policy` | قواعد تولید خروجی برای یک نوع مطالعه |

هر فایل زیر `content/` یک رکورد است و نام آن با `id` برابر است. فولدرها صرفاً برای مرتب‌سازی‌اند؛ شناسه‌ها و ارتباط‌ها ساختار واقعی را تعریف می‌کنند.

## فیلدهای مشترک

| فیلد | معنا |
|---|---|
| `schemaVersion` | نسخهٔ قرارداد؛ فعلاً `1.0.0` |
| `id` | شناسهٔ ثابت، انگلیسی و با خط تیره |
| `type` | نوع رکورد |
| `subjectIds` | حوزه‌های مرتبط؛ مستقل از مسیر فایل |
| `title` | عنوان‌های زبان‌دار، مانند `fa` و `en` |
| `tags` | برچسب‌های جست‌وجو |
| `status` | `draft`، `reviewed`، `published` یا `archived` |
| `visibility` | قصد انتشار: `private` یا `public` |
| `provenance` | منشأ استخراج/تدوین/تولید، وضعیت بررسی و ارجاع‌ها |
| `payload` | دادهٔ اختصاصی هر نوع |
| `extensions` | توسعه‌های نام‌دار، مثل `physics.units` |

`origin: extracted` یعنی اطلاعات از منبع برداشت شده؛ به معنی تأیید صحت آموزشی نیست. `editorial` شامل دسته‌بندی، بازنویسی یا استنباط در این مرحله است. `generated` برای محتوای تازهٔ تولیدشده توسط مدل در آینده است.

ارجاع‌ها `sourceId` و `locator` دارند؛ نقل قول کوتاه اختیاری است. شمارهٔ پیام در این استخراج، شماره در **۱۶ پیام مشاهده‌شده** است و شناسهٔ اصلی یا دائمی ChatGPT نیست. شمارهٔ جدول نیز درون همان پیام شمرده شده است.

مقدار ناشناخته را `null` بگذاریم و علت را در `missing` یا یادداشت ثبت کنیم. تاریخ نسبی مانند Thursday یا Today به تاریخ قطعی کلاس تبدیل نمی‌شود. اگر تاریخ واقعاً مشخص شد، `occurredAt` با قالب ISO ثبت و `datePrecision` اصلاح می‌شود.

## بلوک‌های آموزشی

بلوک‌ها قرارداد مشترک `id / type / version / data` دارند. نسخهٔ ۱ این نوع‌ها را پشتیبانی می‌کند:

`text`, `question`, `example`, `formula`, `comparison`, `timeline`, `quiz`, `code`, `media`, `extension`

متن ساده و Markdown در `text` پشتیبانی می‌شوند. Markdown متن محتواست؛ JSX و کد MDX دریافتی از مدل اجرا نمی‌شود. مثال، مقایسه و فرمول دادهٔ ساختاریافته دارند تا تبدیل‌کننده مجبور به استخراج معنا از رنگ و HTML نباشد.

برای محتوای تازه‌ای مثل مدار الکتریکی:

```json
{
  "id": "block-resistor-circuit",
  "type": "extension",
  "version": 1,
  "data": {
    "namespace": "physics.circuit",
    "fallbackText": "یک باتری به مقاومت متصل شده است.",
    "value": { "resistanceOhms": 220 }
  }
}
```

نمای تعاملی می‌تواند `value` را بفهمد؛ خروجی متنی از `fallbackText` استفاده می‌کند. اعتبارسنج اختصاصی این extension هنگام ساخت ماژول مدار اضافه خواهد شد. این سازوکار جایگزین اعتبارسنجی دادهٔ حوزه‌ای نیست.

## واژگان و جلوگیری از تکرار

هر واژه/عبارت یک شناسه دارد؛ هر معنای مستقل نیز شناسهٔ خودش را دارد. `take up` در دادهٔ حاضر دو معنی دارد: شروع سرگرمی و اشغال زمان. تکرار واژه در جلسهٔ تازه یک `occurrence` می‌سازد و در صورت وجود معنای جدید، یک `sense` افزوده می‌شود.

معنی فارسی، تعریف انگلیسی و معادل‌ها جدا هستند. وقتی منبع فقط synonym داشته، `definition.en` خالی مانده است. نقش دستوری مرکب مثل `Verb / Noun` از منبع حفظ شده و بعداً می‌توان آن را به معناهای دقیق‌تر تفکیک کرد.

در استخراج اولیه، ردیف‌هایی که دقیقاً معنی فارسی و نقش دستوری یکسان داشته‌اند، یک sense گرفته‌اند؛ تفاوت‌های ترجمه حفظ شده و ممکن است پس از بررسی ادغام شوند. همهٔ ۱۷۷ ردیف مبنا در `imports/visible-vocabulary-rows.json` موجودند. ردیف‌های واژگان بدون شمارهٔ نمایشی جدول ذخیره شده‌اند؛ این فایل رونوشت دقیق فایل Excel نیست.

خانوادهٔ کلمات یک collection مستقل است. مشتق و صرف یکی نیستند: رابطهٔ `instructions → instruction` از نوع `inflection-of` است. شکل تأییدنشدهٔ یک کلمه را برای کامل‌کردن جدول نمی‌سازیم.

## ارتباط‌ها و مسیر

هر رابطه `from / type / to` و ارجاع دارد. نوع‌های رابطه:

`covers`, `contains`, `related-to`, `requires`, `illustrates`, `member-of`, `inflection-of`, `derivation-of`, `contrasts-with`, `revises`

`A requires B` یعنی B پیش‌نیاز A است. `unlocks` از معکوس همین رابطه ساخته می‌شود و دوباره ذخیره نمی‌شود. تنها رابطهٔ accepted از نوع requires می‌تواند مبنای محدودیت مسیر باشد. ارتباط مفهومی و ترتیب مشاهدهٔ جلسات به معنی پیش‌نیاز نیست.

در استخراج فعلی تمام رابطه‌ها **proposed** هستند؛ بیشترشان پوشش موضوع یا عضویت در خانواده‌اند. هیچ پیش‌نیاز آموزشی به‌عنوان حقیقت قطعی اختراع نشده است. چرخه در requires و ارجاع به شناسهٔ ناموجود رد می‌شود.

## تغییر و نسخه‌بندی

- عنوان، چیدمان یا مسیر فایل عوض شود، `id` عوض نمی‌شود.
- شناسهٔ معناها نیز پس از ایجاد ثابت می‌ماند؛ در این استخراج نخست با شناسهٔ محتوایی ساخته شده‌اند.
- اصلاح متن اصلی را بازنویسی نمی‌کند؛ یک correction یا نسخهٔ Writing تازه می‌سازد.
- تغییر ناسازگار در ساختار به نسخهٔ جدید قرارداد و اسکریپت مهاجرت نیاز دارد.
- تاریخچهٔ ویرایش‌ها از Git می‌آید؛ تاریخ‌ها و پیشرفت فرضی تولید نمی‌شود.
- پیشرفت، زمان مطالعه و پاسخ شخصی کاربران جزو محتوای مرجع نیستند. محل ذخیرهٔ runtime آن‌ها در مرحلهٔ سایت طراحی می‌شود.

ساختارها در [JSON Schema رکورد](../schemas/record.schema.json) و [رابطه](../schemas/relation.schema.json) تعریف شده‌اند. مبنای قرارداد از [JSON Schema](https://json-schema.org/understanding-json-schema/reference/object) پیروی می‌کند؛ فیلدهای جدید از مسیر extension یا تغییر نسخه اضافه می‌شوند.
