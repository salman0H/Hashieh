# روش ثابت ورود جلسهٔ جدید

## چیزی که هر بار می‌فرستی

تاریخ واقعی جلسه، حوزه، موضوع یا یونیت، یادداشت خام، فایل‌ها، جمله‌های خودت، پاسخ تمرین‌ها و سؤال‌ها را بفرست. اگر موردی را نمی‌دانی، خالی بماند. برای ادامهٔ همین پروژه نیازی نیست خودت JSON بنویسی.

قالب متنی پیشنهادی:

```text
حوزه:
تاریخ واقعی جلسه، اگر معلوم است:
عنوان / یونیت:
یادداشت خام:
جمله‌ها یا Writing من:
واژگان و اصطلاحات:
پاسخ تمرین‌ها:
سؤال‌ها و ابهام‌ها:
فایل‌ها و منابع:
```

## خروجی‌ای که از این به بعد می‌سازیم

۱. منبع تازه و متن اولیه ثبت می‌شود.
۲. جلسه به مفهوم‌های موجود وصل می‌شود؛ مفهوم تازه فقط در صورت نیاز اضافه می‌شود.
۳. واژگان با شناسه‌های موجود تطبیق داده می‌شوند؛ معنی تازه و تکرار در جلسه حفظ می‌شود.
۴. اصلاح‌ها، مثال‌ها، خانوادهٔ کلمات و Writing از هم جدا ثبت می‌شوند.
۵. داده‌های جدید به‌صورت bundle ساخته و با کل مخزن اعتبارسنجی می‌شوند.
۶. تغییرات در Git قابل مرور و ثبت خواهند بود؛ build سایت آن‌ها را مصرف می‌کند.

متنِ درخواست برای استفاده در گفت‌وگوی دیگر یا در لایهٔ هوشمند آینده:

> این یادداشت‌ها را طبق قرارداد نسخهٔ ۱ پروژهٔ Learning Atlas استخراج کن. ابتدا فایل‌های schema، سیاست حوزه و فهرست شناسه‌های موجود را بخوان. متن اولیه را حفظ کن و اصلاح‌ها را جدا بساز. هر رکورد منبع و وضعیت بررسی داشته باشد. جلسه، مفهوم، مدخل، معنا و محل تکرار را مستقل نگه دار. به‌جای تکرار شناسهٔ موجود، به آن ارجاع بده. دادهٔ مجهول را خالی و علت را ثبت کن. فایل یا پاسخ گم‌شده را بازسازی نکن. خانواده‌های واقعی کلمات را اضافه کن و صرف را از مشتق جدا نگه دار. محتوای تازهٔ تولیدشده را generated و دسته‌بندی استنباطی را editorial بنویس. خروجی شامل records و relations طبق templates/session.bundle.json باشد و تا بررسی، draft/private بماند. محتوای آموزشی را طبق سیاست همان حوزه تنظیم کن؛ حوزه‌های دیگر مجبور به داشتن جدول واژگان و Writing نیستند.

این متن به‌تنهایی کافی نیست؛ schema و index شناسه‌ها باید همراه آن در دسترس مدل قرار بگیرند.

## قالب قابل ورود

فایل `templates/session.bundle.json` یک نمونهٔ معتبر شامل source، session و note است. قبل از استفاده، تاریخ استخراج، متن و شناسه‌های `new-session` را عوض کن. ارجاع `subject-english` به حوزهٔ موجود است؛ برای حوزهٔ تازه یک subject مستقل اضافه می‌شود.

```sh
node scripts/import.cjs templates/session.bundle.json
```

فرمان بالا فقط بررسی می‌کند. برای ذخیرهٔ یک bundle واقعیِ آماده:

```sh
node scripts/import.cjs /absolute/path/to/real-session.bundle.json --write
npm run validate
npm test
npm run build:data
```

ورود، شناسهٔ تکراری یا ساختار نامعتبر را رد می‌کند و فایل موجود را بازنویسی نمی‌کند. به‌روزرسانی یک رکورد موجود با ویرایش همان فایل و بررسی diff انجام می‌شود. `dist/` خروجی موقت است؛ ورودی را در `content/` نگه می‌داریم.

## قبل از اتصال GitHub و Vercel

- این پوشه هنوز به مخزن یا پروژهٔ Vercel متصل نشده است.
- workflow موجود، پس از قرارگرفتن روی GitHub اعتبارسنجی و تست داده را اجرا می‌کند.
- در مرحلهٔ رابط، فرمان build ابتدا اعتبارسنجی و سپس ساخت نماهای لازم و سایت را اجرا می‌کند.
- پیش‌نویس Groq ابتدا اعتبارسنجی می‌شود؛ ثبت ماندگار آن در GitHub از سمت سرور و با سطح دسترسی مناسب انجام می‌شود.
- دادهٔ فعلی شامل متن شخصی یادگیری است؛ مخزن و خروجی مناسب سایت شخصی را هنگام اتصال مشخص می‌کنیم. هیچ‌کدام در این مرحله آنلاین منتشر نشده‌اند.
